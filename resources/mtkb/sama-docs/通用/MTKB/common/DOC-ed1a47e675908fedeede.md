- 型号：未标注
- 验证状态：原始资料/待工程验证

## 一、具体机床分类

具体机床采用七级分面分类：

1. 机床大类：磨床、车床、加工中心等。
2. 机床子类：平面磨床、外圆磨床、无心磨床等。
3. 品牌：中文品牌名与英文品牌名并列。
4. 机型：使用铭牌型号；未知时使用 `待确认型号`。
5. 知识性质：`原理与说明书`、`实例与工程`、`维修案例`。
6. 技术种类：机械、电气、CNC/NC、PLC/PMC、FP/HMI、伺服主轴、液压气动、通信网络。
7. 资料形态：说明书、电路图、源工程、参数备份、日志、测试记录等。

## 二、品牌与磨床子类

- 法力图/FAVRETTO：优先归入平面、导轨、转台磨床，最终以机型为准。
- 三井/MITSUI：优先归入精密平面磨床，最终以机型为准。
- 斯图特/STUDER：按机型归入外圆、万能圆筒或内圆磨床。
- 丰田/TOYODA-JTEKT：按机型归入外圆、内圆、曲轴、凸轮或非圆磨床。
- 米克罗莎/MIKROSA：优先归入无心外圆磨床，最终以机型为准。

一个品牌可以出现在多个磨床子类中，不能只按品牌判断机床类型。

## 三、文件命名

普通资料推荐格式：

`品牌_产品或机型_主题_版本_语言_状态.ext`

示例：

- `FANUC_0i-F_参数说明书_B-64610CM01_ZH_官方.pdf`
- `MIKROSA_待确认型号_PLC工程_现场备份_待验证.LAD`
- `STUDER_待确认型号_FP工程_设备36_待验证.zip`

机床工程内部文件不得为了符合命名规范而重命名。应在工程外层目录和索引中记录规范名称。

## 四、状态字段

- `原始资料`：未经整理的官方或现场原始文件。
- `待确认`：机型、版本、来源或适用范围尚不明确。
- `已验证`：已在对应机床或仿真环境核对。
- `已废弃`：不再适用但需要保留历史记录。

案例另设验证状态：`未核实`、`桌面分析`、`待现场验证`、`现场已验证`、`已修复待复测`、`已关闭`。资料状态与验证状态不得混用。

## 五、案例与梯形图记录

1. 所有案例使用 `统一案例模板.md`，保留任务、方法和总的问题总结；缺失字段写 `未提供`，数据库存 `NULL`。
2. 案例编号使用 `CASE-YYYYMMDD-品牌-型号-三位序号`。
3. 梯形图分析必须把地址、注释/符号、程序、网络、指令、来源和验证状态一并记录。
4. 地址与注释冲突时，只能标为待核实；在电气图和现场确认前，不得仅凭地址或仅凭注释判定接线错误。
5. 具体规则见 `案例数据库规范.md`；结构化数据见 `案例数据库/机床案例库.sqlite`。

## 六、禁止直接进入全文检索的文件

- 编译产物：MEM、FPPBIN。
- 二进制图形：FIG。
- 临时文件：TMP、LOG、空的错误文件。
- 完整工程中的系统生成列表文件。

这些文件作为附件保存，通过工程说明和元数据参与检索。
