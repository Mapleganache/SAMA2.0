## 机床案例数据库

`机床案例库.sqlite` 是当前知识库的结构化索引，原始程序、图纸和报告仍保存在各自源文件中，不写入二进制大字段。

## 当前数据

- 设备：2 台/型号
- 案例：2 个
- 固定案例字段：每个案例 11 项，缺失项保留为 `NULL`
- 梯形图问题：41 项，其中高风险 17、中风险 16、注释质量 8
- 问题涉及的规范地址：144 个
- 来源记录：10 份

所有问题当前均为桌面分析、待现场验证；数据库中的“建议”不表示已经修改设备。

## 文件

- `schema.sql`：表、约束、索引和视图。
- `build_case_database.py`：从两份梯形图说明和两份分析报告重建数据库。
- `机床案例库.sqlite`：可直接使用 SQLite 打开。

## 常用查询

查看案例完整度：

```sql
SELECT * FROM v_case_completeness;
```

查看高风险问题：

```sql
SELECT issue_id, title, subsystem, network_ref, verification_status
FROM issue_findings
WHERE risk_level = '高'
ORDER BY case_id, original_code;
```

按地址同时查看注释和关联问题：

```sql
SELECT issue_id, issue_title, canonical_address,
       primary_comment, comment_at_analysis, comment_status,
       evidence_status
FROM v_issue_signal_context
WHERE canonical_address = 'X8.4';
```

查缺少注释的地址：

```sql
SELECT equipment_id, canonical_address
FROM signals
WHERE comment_status = '缺少注释'
ORDER BY equipment_id, address_area, address_number, bit_number;
```

## 重建

在工作区根目录执行：

```bash
python3 '机床智能体知识库/00_知识库规范/案例数据库/build_case_database.py'
```

脚本会重新生成数据库并检查设备数、案例数、固定字段数、问题数、地址关联和外键完整性。若原分析报告新增问题，应同步调整脚本的预期数量后再重建。

## 后续录入规则

1. 先用 `../统一案例模板.md` 建立人可读案例。
2. 再向 `cases` 和 `case_sections` 写入主记录及固定字段。
3. 每个梯形图问题单独写入 `issue_findings`。
4. 地址进入 `signals`，各网络注释进入 `signal_comments`，问题和地址通过 `issue_signals` 关联。
5. 地址与注释冲突时保留两者，状态写待核实；现场验证后才能更新为已验证或已关闭。
