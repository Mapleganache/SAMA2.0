# SAMA 2.0 · 数控机床故障诊断 Agent

[English](README.md) | **中文**

SAMA 2.0 是一个面向数控磨床/机床的故障诊断 Agent。输入机型、工况、冷热态、现象或报警号后，它会检索本地知识库与历史案例，生成多路候选方案，再由 Judge 评分选优，最终给出**待验证的主方向、排查步骤和引用来源**。

它不是通用聊天机器人，而是一条带门控、检索、多路采样、评分和依据检查的诊断流水线。

> **数据库声明（使用前必读）**
>
> 本仓库**不自带任何机床知识数据**。要正常使用 SAMA，**必须自行导入并补充自己的数据库**。
> 没有数据库时，软件只能读取 `knowledge/` 里的 6 篇演示用短笔记，检索与诊断能力非常有限。
> 导入方法见[数据库声明](#数据库声明)和[使用说明第 7 节](使用说明.md#7-导入数据库详细教程)。

## 功能

### 输入识别

从一段口语化的描述里自动提取诊断需要的信息，中英文都支持。

- 认出机床家族和型号，比如 STUDER、高桥、MIKROSA，以及外圆、内圆、无心、平面磨床和加工中心。
- 认出故障现象：发热、振动、异响、精度或表面超差、爬行卡滞、漏油、换刀异常、启动异常、报警。
- 认出工况：空载还是磨削中，冷机还是热机。
- 认出限制条件：不能停机、没有备件、没有量具、不允许拆卸，这些会影响推荐方案，不会被忽略。

### 问题分流

不是所有问题都走同一套流程。

- 概念、原理、选型这类知识问题，直接回答，不用跑完整诊断。
- 故障排查问题才启动完整流程。
- 拿不准的情况会再判断一次，避免简单问题被过度处理。

### 追问补充

- 机型、现象、空载/磨削、冷热态这四项缺任何一项都会追问，并说明为什么这很重要。
- 追问最多两次，之后带着明确标注的假设继续，不会卡住不动。
- 补充时只写缺的那一句就行，不用重复整个问题。

### 多方案并行诊断

- 复杂故障会同时从不同角度生成多份诊断方案，而不是只给一个答案。
- 每份方案独立检索资料、独立推理，避免几份方案想法雷同。
- 遇到超时或中途卡住，会收束成一份可用结果，不会整轮白跑。

### 方案评分与推荐

- 按准确性、安全性、现场可行性、完整性、简洁性五个维度给每份方案打分。
- 自动选出一份主推方案，同时给出第二名供对比，方便现场按实操条件再选一次。
- 评分失败时如实标注"未评分"，不会编造分数。
- 单独做一次安全抽查，重点看能量隔离、砂轮防护、是否阻止带电带压操作。

### 准确性复核

- 对推荐方案再做一次复核，给出准确性、可信度，以及机理、具体措施、不确定性表达三方面的评价。
- 复核结论附在回答末尾，方便判断这份方案有多可信。

### 事实核查

这是 SAMA 最重要的一层保护。

- 回答里出现的压力、间隙、扭矩、尺寸等具体数值，必须在本轮查到的资料里真实出现，查不到就明确标注"不能当作事实"。
- 引用编号必须真的来自本轮检索结果，凭空编造的引用会被删掉。
- 本地没有对得上的本机案例时，会明确告诉用户这只是"参考近邻资料选出的待验证方向"，不会硬凑成一份通用清单。
- 用户没提到的数值不会被补造，只认用户原文里写过的读数。

### 知识检索

- 内置本地知识库，覆盖精编条目、原文资料和历史案例，每条都带适用范围、审核状态和限制条件。
- 检索会顺着术语之间的关联往外扩，找到字面上不直接对应但相关的资料。
- 附带机床家族的维修笔记和测点模板，帮助定位该查哪里。
- 本地资料不够时可以开启联网检索补充，联网结果必须标明"来自网络、需核对是否适用于本机"。
- 知识库以只读方式打开，不允许模型自行拼 SQL 查询。

### 界面与接口

- 中英文双语，界面、追问、方案、评分表一起切换，英文模式用英文转述资料但保留引用编号。
- 诊断详情面板展示判定依据、识别到的信息、各方案评分和执行过程。
- 保存最近 12 条提问，点击即可复用。
- 可切换联网兜底、强制多方案、详情显示、深色/浅色主题。
- 支持网页操作和命令行两种用法，也提供 HTTP 接口供其他程序调用。
- API Key 只存在浏览器本地，服务端不写盘、不记日志，不会外泄。

## 效果

在导入有限规模数据的情况下（主要为机械专业书籍与维修案例），SAMA 2.0 的实测表现如下：

| 问题类型 | 原因判断与维修方案精度 |
|---|---|
| 库内已收录的问题 | **90% 以上** |
| 库内未收录的问题 | **35%–45%** |

- **已收录问题**：能准确检索到相关条目，原因判断和维修方案基本可直接作为参考。
- **未收录问题**：系统会检索库内已有资料，把分散的信息整合起来再推理，仍能给出可用的原因方向和维修方案，而不是简单回答"查不到"。
- **两者的差距**说明了数据的价值：数据库中资料越完整，未收录问题能被"推理覆盖"的比例就越高。

> 以上数据来自当前有限语料条件下的内部测试，会随数据库规模、资料质量和机型覆盖范围变化，不构成任何性能承诺。

## 快速开始

```sh
cd sama2.0
npm ci
npm start
```

浏览器打开 <http://127.0.0.1:3920/>，在「设置」里填入 API Key。

### 数据库

数据库是本地 SQLite 文件，**不随本仓库分发**，需要你自行导入。最快的方式是放到 `sama2.0/data/sama_full.sqlite`。详见下方[数据库声明](#数据库声明)，完整步骤见[使用说明第 7 节](使用说明.md#7-导入数据库详细教程)。

### 环境要求

- Node.js **22.13 或更高版本**
- 磁盘预留至少 3 GB（数据库约 1.5 GB）
- 一个兼容 OpenAI 协议的模型服务

## 数据库声明

**本仓库不包含数据库，也不自带任何机床知识数据。** 使用本软件前，你必须自行准备、导入并补充自己的 SQLite 知识库，否则 SAMA 只能读取 `knowledge/` 下 6 篇演示用短笔记，检索能力与诊断质量会明显下降。

- **数据库需自行导入并补充**：数据库不随代码分发，请向维护者索取，或使用团队内部分发的数据库文件；后续新增资料、修正条目也由使用者自行维护。
- **文件形态**：单个本地 SQLite 文件，通常名为 `sama_full.sqlite`，约 1.4 GB；不是远程服务，也不是 MySQL / PostgreSQL。
- **导入方式**：放到 `sama2.0/data/sama_full.sqlite`，或用环境变量 `SAMA2_SQLITE_PATH` 指定路径，或修改 `sama-database.json`。三种方式优先级为：环境变量 → 配置文件 → 默认位置。
- **完整教程**：见[使用说明第 7 节 导入数据库](使用说明.md#7-导入数据库详细教程)，包含分片包还原、接入验证、资料模式选择和换库步骤。
- **不能随便换库**：自行准备的其他 SQLite 文件不能直接使用，必须符合本项目的数据结构版本要求（`release_meta` 中的版本标记）。
- **只读使用**：数据库以只读方式打开，程序不会修改你的数据。
- **不要提交数据库**：数据库文件不应提交到 Git，`sama2.0/data/` 已在 `.gitignore` 中。

> 我们不随仓库提供数据库内容，也不对其完整性、准确性和适用性作任何担保。数据库中的数值、牌号和参数仅作历史参考，不能直接作为本机参数。

## 免责声明

**请在使用前完整阅读。**

1. **非专业维修指令。** SAMA 输出的是待验证的诊断方向和排查建议，不是维修作业票，不能直接作为现场操作依据。
2. **必须人工确认。** 所有结论都应由具备资质的维修人员结合现场情况、设备状态和厂家手册独立判断。拆主轴、拆砂轮、带压/带电检查前，必须完成能量隔离和现场安全确认。
3. **数据仅供参考。** 知识库中的数值、油品牌号、间隙、扭矩和工艺参数仅作历史参考，不能直接作为本机参数。不同批次、不同磨损状态的设备可能有完全不同的适用值。
4. **案例不能等同验证。** 历史案例的机型可能未知或只是相似而非相同，不能当作同型号已验证的维修程序。
5. **审核未完成。** 当前版本的专业审核尚未完成，相关内容会标注待核验，不应作为最终决策依据。
6. **数据完整性。** 原 PDF、LAD、图像未随数据库分发，库内原始文件路径仅为来源元数据，不能假定在其他电脑可打开。
7. **模型输出有不确定性。** 大语言模型可能产生错误、遗漏或看似合理但实际错误的推理，即使通过依据检查也不能排除错误。
8. **责任限制。** 使用本软件产生的任何直接或间接后果，包括设备损坏、人身伤害、生产损失，由使用者自行承担。作者与贡献者不提供任何明示或暗示的担保。
9. **数据合规。** 使用者应自行确保输入内容不含涉密信息、个人信息或无权使用的受版权保护资料。
10. **密钥安全。** API Key 请自行保管，不要提交到 Git 或发给无关人员。
