- 题面只给机型 + 现象，要求直接给原因和处置；
- 参考答案用案例原文的分析 + 处置。


## 三、怎么跑的

- 两个服务并行，同一份 holdout100 库；
- 端口 3941 / 3942；
- 参数：`SAMA2_PACK=0`、`SAMA2_EXPAND=0`、`SAMA2_JUDGE_SHADOW=1`；
- 每题独立请求，`allowWeb=false`、`session=null`；
- 结果：`eval100/run_a.jsonl`、`run_b.jsonl`，合并为 `run.jsonl`；
- 判分：`eval40-score.mjs`，主选/备选分别判原因/处置。

## 四、怎么解读

1. **原因 32%** 与之前 50 题的 34% 基本持平；
2. **处置 16%** 明显低于 50 题的 28%；
3. 这不是同一套题，不能直接说“新库让准确率下降”；
4. 但可以确认：**新增的 444 篇方法文档，没有把 100 题案例诊断的处置能力托起来**；
5. 现象符合预期：
   - 新资料是“怎么调/怎么查”的方法文档；
   - 100 题问的是“这个案例的原因和处置”；
   - 方法文档能补充步骤，但不能替代案例条目。

## 五、下一步

要严格判断“新库有没有用”，最干净的做法是：

> 用同一套 100 题，在**旧库**（`backup/db-before-newfolder-20261119`）上再跑一遍，做配对比较。

否则 32/16 只能说明“这套 100 题当前水平”，不能说明增减。

另一个方向：

- 把这 100 题按“原因题 / 处置题 / 方法题”拆开；
- 方法题（M19、刀塔、电池、水平）单独评测，才看得出新资料的价值。
