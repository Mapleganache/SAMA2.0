## 四、错误回答的特征（17 题）

### 4.1 三类主要失败模式

**① 子系统/部件错位（最常见）**

把故障归到相邻但错误的系统：

- 参考是主轴轴承/传动键 → 方案查导轨润滑/爬行（S008、S009、S013）；
- 参考是电气/伺服/参数 → 方案查液压、电磁阀、导轨（S030、S036、022）；
- 参考是刀架齿盘卡屑 → 方案查导轨润滑（S016）。

**② 具体参数/位号/数值缺失**

方向大致对，但答不出关键那一位：

- 004：知道 `024#`，但没指出第三位应置 0；
- 017：没提 `PRM527` 进给上限；
- 025：没给 `1815` APZ/APC 置位；
- 029：没提 `124#` 参数变大；
- 012：没识别 DRY 试运行信号；
- 013：没识别 `F0.2` 过小与 G98 改法。

**③ 处置与参考不一致**

原因勉强沾边，但动作不是参考的排除路径：

- 002：参考初始化磁泡存储器，方案查显示链路/急停；
- 014：参考换电池，方案查显示器高压；
- S017：参考反馈信号处理板，方案按换刀未到位查；
- 030：参考 M 功能继电器粘连，方案查 APC 互锁。

**方向对，但停在“泛化正确”**：

- 001：知道参数丢失，但没确认 417/427、没按 PWE 步骤；
- 004：知道 `024#`，但没指出第三位；
- 007：知道回零/编码器，但没给“脱开编码器手转校正”；
- 018：知道 Scale 接口，但没锁定接口板、没给交叉验证；
- 019：知道软限位，但把雷电干扰降为次要；
- 023：知道参考点，但没给 `1815` 重设；
- 024：只泛化到“参数丢失/信号异常”，没给 K1.1；

**共同点**：

```
原因方向 ≈ 参考

```

## 六、对 Agent / Judge 的启示

1. **正确回答的核心不是“写得多”，而是“命中具体案例/具体位号”**；  
   长度、是否提参数都不能区分对错。

2. **错误回答最常见的是“子系统错位”**：  
   主轴→导轨、电气→液压、参数→电磁阀。

3. **部分正确是“方向对、落点错”**：  
   这类最容易被 Judge 的“完整性/机理分”高估。

4. **Judge 应优先看“是否引用了同现象案例/同参数位号”**，而不是作文分；  
   这与 `Agent与Judge代码审查报告` 的 P0 一致。

5. **MMR 入口的价值**：  
   50 题处置 14→16、任一方案 17→18；  
   它改善的是“候选覆盖”，但主选原因没变，说明瓶颈在选优。

## 七、一句话

> **对的回答：命中同现象案例 + 给出具体位号/部件/动作。**  
> **错的回答：子系统错位，或方向对但答不出关键那一位。**
