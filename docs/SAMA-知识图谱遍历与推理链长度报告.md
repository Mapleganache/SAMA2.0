# SAMA 知识图谱遍历与推理链长度报告

日期：2026-11-09
对象：`sama2.0/retrieval-tree.mjs` + `sama2.0/sama-sqlite/term-graph.mjs`
生产库：`sama2.0/data/sama_full.sqlite`（v2，204,894 片段，5,426,991 postings）
结论：**设计为 2 跳、硬上限 16 跳，但生产上实际稳定只走 1 跳；非磨床域在图里没有节点，无法扩展。**

## 一、算法在图里怎么走

代码：`retrieval-tree.mjs:262-373`

### 1. 入口（第 0 跳）

- 五路各自按温度 τ（0.35 / 0.5 / 0.85 / 1.0 / 0.95）对桥接词做 softmax，生成入口查询 `t0`；
- 用 `t0` 检索 BM25/FTS，取 **top-K = 3** 篇作种子文档；
- 种子词 = `bridgeTerms(t0)` 前 4 个（如 爬行 / 导轨 / 润滑 / 油品）；
- 打分 `S0 = scorePathSet(origin, 种子词, 种子文档)`。

### 2. 扩展（第 n 跳）

对 beam 中每条路径 π：

1. 用 π 的全部词拼查询，检索 **top-K 篇未见过**的文档；
2. 候选新词 = 命中文档抽词 + **词图邻居**（`corpusNeighbors`）；
3. 每个候选词 c 拼新查询，再检索新文档；
4. 计算：

```
S_n   = scorePathSet(origin, π.terms ∪ {c}, 累计文档)
gain  = 新文档自身的相关度
ΔG    = γ^(n-1) × (gain − λ)      γ = 0.6，λ = 0.15
G     = π.G + ΔG
```

5. `ΔG ≤ 0` 直接剪枝；beam 按 G 保留 K = 3 条。

### 3. 停机

- 没有候选词，或候选词检索不到新文档 → 停；
- 硬上限：`hardCap = min(hopFuse=16, hops)`；但默认 `hops === TREE_HOPS(2)` 时条件不成立，**实际硬上限是 16**；
- 业务上真正起作用的是 **ΔG 软停机**。

### 4. 输出

`hopsUsed`、`path`（词序列）、每跳的 `query / records / S`，格式化成树文本交给五路 ReAct。

## 三、为什么实际只有 1 跳

### 1. topK=3 太小（直接原因）

种子 3 篇已经是最好的；第 2 跳用扩展查询检索，回来的还是这 3 篇，`newDocs` 为空 → 没有候选 → 直接停。

### 2. λ=0.15 不低

第二跳要求 `gain > λ`；没有新文档时 `gain` 取不到，`ΔG` 恒为 0，永远不满足。

### 3. 词图只有 48 个节点（结构性原因）

`term-graph.mjs:9-16` 的 `LEXICON` 是写死的磨床/润滑词表：

```
爬行 导轨 润滑 油品 润滑脂 添加剂 抗磨 乳化 进水 间隙
供油 节流 污染 中心孔 顶尖 皂液 油漆 汽油 抗水性 抱轴
烧伤 粗糙 波纹 振纹 超差 齿面 发热 温升 过热 发烫 卡滞
抖动 滞涩 油膜 机械油 导轨油 静压 动静压 轴承 主轴 液压
油腔 低温 抗乳化 补脂 密封 丝杠 咬毛 拉毛
```

**没有换刀、刀库、伺服、编码器、报警、参数**——加工中心/车床类问题在图上没有邻居可走。

### 4. 图的方向性示例（磨床域有效）

```
爬行 → 拉毛(6.62) 导轨(4.44) 丝杠(3.91) 间隙(3.43) 抗磨(4.29)
导轨 → 导轨油(6.06) 滞涩(6.06) 超差(4.50) 爬行(4.44) 抖动(4.16)
油品 → 机械油(5.68) 添加剂(4.92) 乳化(4.67) 抗磨(4.61) 汽油(4.38)
抱轴 → 咬毛(8.04) 拉毛(7.53) 静压(5.46) 油膜(5.37) 动静压(7.48)
```

磨床域边权很强，说明图本身可用，问题在**覆盖域**和**扩展门槛**。

## 四、影响

1. **“多跳检索树”名不副实**：生产上等价于单跳 BM25 + 桥接词扩展；
2. **非磨床问题拿不到图的收益**：换刀、刀库、报警这些词没有节点；
3. 图扩展的收益只有在 `topK=8 / beam=7` 时才出现（G +28%），但当前默认参数下不会触发；
4. 另有一个独立问题：换刀/#411 题的第一篇都是 `sqlite_curated:7`（顶尖咬毛），属于 curated 排序噪声，与图无关。

---

## 五、建议

| 优先级 | 动作 | 预期 |
|---|---|---|
| P0 | 默认 `topK` 3→8、`beamK` 3→7，用 50 题库内/库外对比 | 2 跳能触发，验证 G 提升是否转化为准确率 |
| P0 | 记录每次查询的 `hopsUsed / path / ΔG` 到日志，统计分布 | 知道多少题真的需要 2 跳 |
| P1 | `LEXICON` 扩域：换刀、刀库、刀塔、伺服、编码器、报警、参数、主轴 | 非磨床题也能扩展 |
| P1 | 或改为从 `full_postings` 高频词自动建图（按 PMI 截断） | 图覆盖不再依赖手写词表 |
| P2 | 视效果调整 λ（0.15→0.08）或 γ | 降低第二跳门槛 |
| P2 | 把 `hops` 显式设为 2，避免默认落到硬上限 16 | 行为可控 |

## 七、结论

**当前不是“图没建好”，而是“图只覆盖磨床润滑域 + 扩展门槛太高”。**

- 磨床题：1 跳就够用，图主要起“桥接词扩展”作用；
- 非磨床题：图完全没参与；
- 想要真正的 2 跳，先改 `topK/beam` 并记录跳数分布，再谈扩词表。
