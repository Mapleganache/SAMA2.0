目的：在上一轮“K=7、γ=0.8”基础上，调整 hops、λ（hopCost）、ρ（beam 随机度），寻找更优组合。

---

## 一、结论

**网格内最优：hops = 4、λ = 0.05、ρ = 0.2**

- 原因 5/25、处置 5/25；
- “任一方案”原因 7/25、处置 7/25，是 12 组里唯一 7/7；
- 同 25 题基线：**原因 10/25、处置 7/25**。

> **网格最优仍明显低于基线（5 vs 10），不建议直接采用。**

## 四、规律

1. **λ=0.05 优于 0.10**：  
   λ=0.10 的组处置普遍只有 2–4/25，λ=0.05 组多在 5/25。

2. **ρ=0.2 优于 0.4**：  
   在 λ=0.05 时，ρ=0.2 的两个 hops 组都优于对应 ρ=0.4。

3. **hops 不是越多越好**：  
   hops=2 与 hops=4 都能到 5/25；hops=3 没有优势。

4. **交互明显**：  
   - hops=4 / λ=0.05 / ρ=0.2：任一 7/7；
   - hops=3 / λ=0.10 / ρ=0.4：全场最差（2/3）。

---

## 五、为什么整体低于基线

本次不是单变量实验，固定项同时改了 6 个：

| 参数 | 基线 | 本次 |
|---|---:|---:|
| minHops | 0 | **2** |
| noNewStop | 1 | **2** |
| maxStep | 8 | **32** |
| beamK | 3 | **7** |
| topK | 3 | **7** |
| γ | 0.6 | **0.8** |
| retBudget | 12 | **24** |
| λ | 0.15 | 0.05 / 0.10 |

因此 5/25 不能归因于 hops/λ/ρ 本身，最可疑的是：

1. `minHops=2` 强制第二跳，带入噪声；
2. `maxStep=32` 让模型在证据不足时继续扩写；
3. `topK=7` 引入更多弱相关文档；
4. `retBudget=24` 放大低质量路径。

## 六、建议

### 不建议

- ❌ 直接把 hops=4 / λ=0.05 / ρ=0.2 设为默认；
- ❌ 在当前固定项下继续扩网格。

### 建议：固定项消融（每次只回退一项）

从网格最优组出发：

```
最优组（hops=4, λ=0.05, ρ=0.2）
  ├─ A：maxStep 32 → 8
  ├─ B：minHops 2 → 0
  ├─ C：topK 7 → 3
  └─ D：retBudget 24 → 12
```

每组 25 题，观察是否回到 10/7 附近：

| 结果 | 结论 |
|---|---|
| 某一组恢复到 9–10/25 | 该项是主因，回退它 |
| 都只有 5–6/25 | 需要同时回退多项，说明该区域整体不适合 |
| 恢复到 ≥10/25 且优于基线 | 保留 hops/λ/ρ 的增益 |

### 最终目标

- 先恢复到基线 10/7；
- 再在基线上单独加 hops/λ/ρ，确认是否有 +1 以上收益；
- 最后才做 50 题验证。
