## 4. 问题清单

### P0：证据 Judge 在库外硬覆盖总分（当前最大问题）

**现象**

- 20 题库外：基线 5/3 → 当前 1/0；
- 库外没有精确条目，所有方案 `tier ≤ 2`；
- 只要引用任意 SUPPORT，就按字典序压过“没引用但方向正确”的方案；
- 库外常退到同一篇泛化文档（如 `sqlite_fragment:204412`），于是“引用泛化 SUPPORT”反而成了优势。

**证据**

- 001/S001/003/S002 多题主选引用同一片段；
- 003 曾经“备选 yes/yes、主选 partial/no”，说明正确方案存在但被换掉；
- Judge 的 coverage 常只有 6%–15%，仍按 tier 2 覆盖。

**影响**

- 库外准确率被压到 1/20；
- 用户看到“推荐”，但方向是泛化的。

**建议**

```
允许证据覆盖总分的条件（满足其一）：
1) tier = 3（精确 CASE/AL/PARAM 条目）
2) tier = 2 且 coverage ≥ 0.30
3) tier = 2 且 证据分 ≥ 7

否则：按总分排序，证据只展示。
库外/无精确条目：Judge 影子模式，不改变 winner。
```

### P1：数据层天花板（库外无解）

- 库外 50 题中 34/50 只能“无法可靠诊断”；
- 缺少精确案例/报警/参数时，检索只能给泛化方向；
- E 盘库不可用，v2 库已是最优；
- 要提升只能按 v2 管线重跑源资料，补实体表。

### P2：自适应 D_pack 未单独验证

- 有 SUPPORT 时 M=5，无 SUPPORT 时 M=8–10；
- 方向合理，但和 Judge 改动一起上，无法归因；
- 可能稀释上下文，也可能帮助召回；
- 需要单独 A/B。

### P3：回树通道需要回归验证

- `expand_tree` 已接入，但当前 20 题里回树触发次数、ΔG 效果未统计；
- 需确认：复杂题不再出现裸 `search_knowledge`、每路最多 1 次、ΔG≤0 不写回。

### P4：评测噪声与小样本

- 20 题样本约 ±2 题波动；
- Judge high/low 可造成 3–11 题差异；
- 首次判分曾因 API 瞬时失败退出，重跑才成功；
- 结论应基于 50 题 + 固定判分口径。

### P5：代码可维护性

- 元素/IDF 代码仍在，但默认关闭，形成“双路径”；
- `retrieval-tree.mjs` 同时保留元素入口与旧模板入口，靠 `useElements` 开关；
- 缺少端到端 Judge 测试（目前只有 scorer 单测 + 流程测试）；
- 部分环境变量/开关未写入文档。

### P6：旧图谱缺陷仍在（未部署修复）

- BRIDGES 团连边、MECHANISM 滑动窗、无序邻居、maxNbr 截断仍在 v1 图；
- 带类型边方案设计正确，但实现后 0/20，已回滚；
- 在数据/选优问题解决前，不建议再动图。

## 5. 根因分析

```
数据层：库外没有精确条目        → 检索只能给泛化方向
   ↓
检索层：正确证据可能进候选      → 但不保证进 pack
   ↓
打包层：M=5 可能挤掉相关片段    → 弱证据时更明显
   ↓
选优层：tier 2 硬覆盖总分       → 泛化 SUPPORT 赢过正确方向
   ↓
成稿层：写得完整但不对          → 判分 partial/no
```

核心矛盾：

> **系统能“找到一些证据”，也能“写出像样方案”，但没有可靠机制判断“这份方案是否对上了本机那条精确证据”。**
