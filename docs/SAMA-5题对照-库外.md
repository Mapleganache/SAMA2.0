## 001｜CNC　FTC—20 型数控车床

**问题**：CNC　FTC—20 型数控车床，机床正在运转时，外部电网突然断电。重新送电后，CRT 上显示出一些 乱七八糟的光亮点，操作面板上所有的信号灯都不亮，各个操作按键和旋钮也全部都 失灵。。最可能的原因是什么？应该怎么处置？请直接给出答案，不要向我提问。

### SAMA 的回答（主选）

检索命中案例条目例040（id：sqlite_fragment:203856），下面按该条目的现象与处理选一个待验证主方向；案例机型为 CK3263/FANUC 0T，与本机 CNC FTC—20 不完全同型，具体系统型号和参数体系需在本机核对后套用，不能直接认定为唯一原因。

### 原因（待验证）

**待验证主方向：外部电网突然断电造成 CNC 系统参数/存储区内容丢失或紊乱、系统起动自检未完成（系统瘫痪），导致 CRT 显示乱七八糟的光亮点、操作面板所有信号灯不亮、按键和旋钮全部失灵。**

依据案例条目例040（id：sqlite_fragment:203856）：一台 CK3263/FANUC 0T 数控车床通电后 CRT 不能进入工作界面并显示无法识别的乱码，检查分析为电池耗尽、数控系统已经瘫痪，必须重新安装机床程序、输入加工参数并进行整机调试。该条目的“CRT 乱码/不能进入工作界面”与本例“CRT 乱七八糟光亮点”对应，可作为首选待验证方向。

本机未提供系统型号、电池状态和上电自检结果，因此不能确认就是电池耗尽或参数丢失；断电冲击也可能同时影响操作面板供电或面板—CNC 接口，需在下面步骤中排除。按原文“机床正在运转时”记录为运转中/热态，未提供磨削工况，按“磨削中”假设保留；原文没有给出任何电压、电池或参数实测值，方案中不补造。

### 方法（仅针对上一节）

1. **安全确认**：断开机床总电源并挂牌，确认外部电网供电已恢复正常、无缺相或异常后，再重新送电；不要在未确认外部供电正常前反复上电。
2. **观察上电起动过程**：重新送电后盯住 CRT，确认是否出现系统版本号、正常界面或自检完成提示。若始终只有乱七八糟的光亮点、没有版本号和正常界面，支持“系统未完成初始化/瘫痪”这一待验证方向。
3. **核对参数丢失迹象**：检查 CNC 系统有无参数类报警、电池报警或“需重新输入参数”的状态指示；检查系统后备电池状态（案例指向电池耗尽，但本机必须以实测和报警指示确认，不能预设）。
4. **核对操作面板供电与接口**：检查操作面板供电回路是否正常带电、面板电源指示有无；检查操作面板与 CNC 系统之间的连接插头/接口是否因断电冲击松动或接触不良。此步用于排除“面板供电或通信中断”这一备选方向，不作为首选主方向。
5. **若确认系统瘫痪或参数紊乱**：按案例条目例040（id：sqlite_fragment:203856）的 FANUC 0 处理思路执行——起动数控系统的同时按下操作面板上的“DELETE”键和“RESET”键，清除残余参数；待显示器出现版本号和正常界面后，将选择开关置于“MDI”，按“PARAM”键进入 SETTING2 界面，将“PEW”设为“1”并打开 EDIT KEY，输入 901# 参数，出现 #100 编程报警时用删除键消除，再输入 900#～939# 系统密级型功能参数；回到 SETTING2 将“PEW”设为“0”、关闭 EDIT KEY，断电后再上电；然后从 000# 参数开始输入机床供应商提供的全部机床参数；将选择开关拨到“JOG”位置手动检查各部分动作；最后输入工件加工程序进行车削试验。上述参数号和按键步骤来自案例条目，套用前必须核对本机 CNC 系统型号和参数说明书。
6. **若清参数后仍无版本号/正常界面**：不要继续盲目重输参数，转查 CNC 电源模块、主板和操作面板接口的硬件状态；此步需要本机电气资料和实测，未核实前不展开拆卸或换件。
7. **记录下一步实测项**：上电后 CRT 显示内容（有无版本号/正常界面）、CNC 参数或电池报警、系统后备电池实测状态、操作面板供电实测状态、面板—CNC 接口连接状态。以上项目未测前，不把“参数丢失”写成已确认的唯一原因。

### 正确答案（原书）

检查分析：1）检查直流电源，5V、15V、24V 电压都正确，保护电池也是完好的。更换记忆单元 电路板MEM—A4 后，CRT 能正常地显示，但是机床仍然不能工作。 2）检查和设定机械参数，发现CRT 上显示： 100P/ SALARM 417X AXIS DGTL PARAM 427Z AXIS DGTL PARAM 其含义是X 轴和Z 轴所设置的参数不正确。经分析，在更换记忆板MEM—A4 时，曾经 取下了保护电池，造成机械参数全部丢失。调出参数表查对，确实如此。
故障处理：按下述步骤重新输入参数。 1）从随机文件中找出“机械参数表”，修改个别与实际不相符的参数。 2）接通“程式保护”，按“PARAM” 键，再按“PAGE” 键，使CRT 显示“设定2” 界面。 3）将PWE 的设置由“0” 改为“1”，再找到“参数” 栏所显示的参数表。需要注意： 参数表中有两套相似的表格，都标有“ PARMTER”。其中，以地址号“0001” 开头的是 “参数”，以地址号“0000” 开头的是“诊断”。 4）将“机械参数” 逐条输入到CNC 中。在输入过程中，如果CRT 上出现“ WARN⁃ ING” 的提示，只需按照英文显示的内容进行操作。 5）输入完毕后复查一遍，确认无误后，再将PWE 的设置由“1” 改回到“0”，至此参 数输入完成。 6）断电后重新起动，操作面板上的信号灯恢复正常显示，按键和旋钮也恢复正常功 能，机床转入正常工作。 1

### 判分

原因：partial；处置：partial

参考原因是换记忆板取下电池致参数丢失，方案主方向为断电致系统瘫痪/参数紊乱，方向相近但未实质命中电池取下这一具体成因；处置含清参重输参数，与参考重输机械参数部分对应，但套用他机型步骤且未核对本机参数体系。

## S001｜数控车床

**问题**：数控车床，某SIEMENES810T/M系统数控卧式平床身车床，车削端面时出现绸纹形状的痕迹，并沿X向具有一定的排列间距规律。 模块一数控车床装调维修9。最可能的原因是什么？应该怎么处置？请直接给出答案，不要向我提问。

### SAMA 的回答（主选）

**说明与假设**：本地命中一条 SIEMENS 数控车床案例条目（sqlite_fragment:204412），但其现象是螺纹加工螺距变动误差，与本机「端面车削出现绸纹、沿X向等间距排列」不是同一现象，故不作为已确认原因，只借其同一条主轴信号链选一个待验证主方向。以下按热机、连续加工工况假设；原文未给切削参数、未给绸纹实测间距，方案中不填任何编造的数值。

### 原因（待验证）

主方向：**主轴每转一周的周期性扰动**，即主轴编码器信号链不稳定——编码器与主轴连接传动带过松、编码器固定松动/污染，或编码器与主轴的传动比参数设置不符（依据：sqlite_fragment:204412，案例S073 对 SIEMENS 数控车床周期性误差给出的原因链为主轴编码器不良、编码器内部脏、编码器与机床固定部件松动、连接编码器传动带过松，以及传动比参数错误）。

推理：端面车削时刀具沿X向按每转进给量逐圈推进，若主轴一转之内编码器信号出现一次丢脉冲、相位抖动或随主轴摆动，切削纹理就会以“每转一个间距”的形式在X向规律重现，形成绸纹状痕迹。该条目的现象（螺纹螺距变动）与本机不同，但两者都指向同一条“主轴转角→位置指令”的信号链，因此把它列为待验证主方向，而不是定论。

需先排除的替代可能：若实测绸纹间距不随主轴每转变化、只与X向位置固定对应，则本条目不适用，方向应转向X轴进给链自身的机械周期（此时不要直接换件，先做下面的周期归属试验）。

### 方法（仅针对上一节）

1. **先做周期归属试验（第一步，决定方向是否成立）**：在不改其他条件的前提下，量出绸纹沿X向的间距，与该工序当前的每转X向进给量对照；再改变主轴转速（或每转进给量）重切一试。若间距随主轴每转同步变化，主轴信号链方向成立；若间距恒定不变，则停在本条，改查X轴进给链的机械周期。
2. **系统侧观察**：在系统诊断/显示页观察主轴实际转速值在稳速段是否出现周期性跳动（与绸纹间距对应的节拍），并核对主轴编码器反馈是否稳定；不要凭手感判断。
3. **按条目核对编码器—主轴连接**（依 sqlite_fragment:204412 的处理项，仅做检查，数值以本机随机文件为准，本方案不给数值）：编码器与机床固定部件有无松动、编码器与主轴之间的连接传动带是否过松、编码器是否污染；同时核对编码器与主轴的传动比参数是否与实际连接一致，参数有误时按系统说明书重新设置（改参数前备份）。
4. **替换性测试**：完成 1～3 后仍不能定位时，按条目所述做替换性判断（用同型号编码器替换对比），替换前做好装配标记与参数备份；未完成前述检查前不先拆主轴部件、不先换机械件。
5. **判定标准**：修复后以同一切削参数复切端面，绸纹沿X向的等间距规律消失或明显减弱，且主轴转速诊断值无周期性跳动，方判该方向确认；否则按第1步结论转入X轴进给链方向另查。

### 正确答案（原书）

检查分析：本例数控车床X向中滑板为燕尾导轨，采用镶条进行导轨间隙调整；传动丝杠为滚珠丝杠，采用直流伺服调速电机驱动。查阅有关资料和故障显示的含义，因系统能执行程序指令运行正常，推断系统基本无故障；用替换法检查伺服电机，
故障处理：原文未给出

### 判分

原因：partial；处置：partial

方案将主轴编码器信号链列为待验证主方向，与参考推断系统基本无故障、应查伺服电机/机械环节的方向不完全一致，且未实质命中参考的镶条间隙与滚珠丝杠检查；处置上做了编码器检查与替换测试，但未覆盖参考的伺服电机替换及导轨镶条、丝杠排查。

## 003｜台湾TNC—20NT 型数控车床

**问题**：台湾TNC—20NT 型数控车床，因数控系统发生故障，重装了FANUC 0T 的数控系统，其后在编辑状态 下，不能输入各种工件的加工程序，无法进行加工。。最可能的原因是什么？应该怎么处置？请直接给出答案，不要向我提问。

### SAMA 的回答（主选）

## 说明与引用
- 本路没有检索到 SUPPORT/NEAR 片段，因此下面只给一个待验证主方向，不展开成通用故障清单。
- 唯一可引用的结构化条目是 `sqlite_fragment:204412`（案例 S073：SIEMENS 系统数控车床螺纹加工螺距变动）。它与本题“重装 FANUC 0T 后 EDIT 状态输不进加工程序”既不属于同一系统，现象也不对应，所以不能作为本机结论，也不能改写成近邻依据；本方案不采用它的处理步骤。
- 保留题面假设：未提供工况，按“磨削中”假设；未提供冷热态，按“热机”假设；现象只按原文“编辑状态下不能输入各种工件的加工程序，无法加工”排查。本题机型为车床且故障点在 CNC 侧，上述工况假设不改变判断方向。
- 本机机型为台湾 TNC—20NT 数控车床，系统已整体更换为 FANUC 0T。“重装系统之后才出现”是唯一明确的时间分界点，排查必须围绕更换系统时被改动过的东西（参数、存储器内容、与面板、PMC 的连接）进行。

### 原因（待验证）
主方向：**重装 FANUC 0T 后，系统侧的“程序编辑许可/写保护”未正确恢复或未正确设置**，表现为 EDIT 状态程序存储区被锁，任何工件程序都写不进去。待验证的具体落点按优先级如下：
1. 面板程序保护钥匙开关位置不对，或开关到系统 PMC 的 KEY1~KEY4 类程序保护信号在重装后未接通（梯形图、接线随系统更换被动过）；
2. SETTING（设定）画面中的写保护/编辑锁定项处于打开状态；
3. 重装时参数未完整灌回（与程序编辑许可、程序存储容量相关的参数），或程序存储区未格式化、容量参数与实装存储板不符——这类情况常表现为“能显示画面但写不进程序”。

证据等级说明：以上是**待验证**方向，不是已确认的唯一原因。目前没有本机实测数据，也没有对得上的本机案例；`sqlite_fragment:204412` 已核对为不适用。

### 方法（仅针对上一节）
只做读取、切换和写入验证，不拆卸、不换件、不设定油压。

1. **读报警原文（第一步，决定后面走哪条路径）**：置 EDIT 模式，手动键入 1~2 个字符，观察 CRT 是否出现写保护类的 PS 报警或提示。逐字记录报警号与英文原文，不要凭印象归类。
2. **验钥匙开关与 KEY 信号**：切换面板程序保护钥匙开关的两个位置，同时在 PMC/诊断状态画面观察对应程序保护信号是否随之翻转。
   - 信号随钥匙翻转 → 钥匙侧正常，转第 3 步；
   - 信号不翻转 → 问题在机床侧开关线路或 PMC 侧，不在系统参数，先查这一段。
3. **查写保护设定与参数完整性**：查看 SETTING 画面中写保护、编辑锁定相关项；再把当前参数与随机备份表、出厂参数表逐项核对，重点核对与程序存储、编辑许可相关的项。此处不给出具体参数号与数值，以本机参数表为准。
4. **验存储区（仅在 1~3 步都正常时做）**：试写一个只有 1~2 行的极短程序，与写入正常长度程序对比。
   - 短程序能写、长程序写不进 → 指向程序存储容量参数与实装存储板不符或存储区未格式化；
   - 短程序同样报写保护 → 回到第 2 步的钥匙、KEY 信号；
   - 没有任何报警但光标不动、字符不显示 → 指向编辑许可参数或键盘、CRT 接口侧。
5. **判定门槛与安全措施**：动手改动任何参数、格式化存储区之前，先完整备份现有参数与已存程序，并记录每一项改动前的原值，便于回退。

**下一步要测的具体项**：① EDIT 下写保护类报警的报警号与原文；② 钥匙开关切换时程序保护信号是否翻转。这两项结果出来即可把主方向收敛到“面板、PMC 侧”或“系统参数、存储区侧”其中一支。

### 正确答案（原书）

检查分析：1）查看FANUC 0T 系统的使用维修手册，0018#参数用于选择编辑操作方式。当其中 的第7 位为“0” 时，是“标准” 操作方式；如果为“1”，则是“编辑B” 操作方式。在这 台机床中，正确的方式应该是“标准” 方式。 2）核对0018#参数，其中第7 位被设置为“1”，这是错误的。
故障处理：将0018#参数的第7 位由“1” 改为“0” 后，工件的加工程序可以顺利输 入，故障得以排除。

### 判分

原因：partial；处置：no

方案把原因指向写保护/编辑许可等泛化方向，未命中参考中0018#第7位（编辑B方式）这一实质原因；处置也未给出将该位由1改0的具体动作。

## S002｜数控车床

**问题**：数控车床，某SIEMENES810T/M系统数控卧式斜床身车床，车削端面时出现接刀不平或平面度失准现象，并无一定的规律。。最可能的原因是什么？应该怎么处置？请直接给出答案，不要向我提问。

### SAMA 的回答（主选）

## 结论先行
本路命中的是同类案例条目（西门子案例S073，`sqlite_fragment:204412`），其故障现象为“随机性误差”，与本机“接刀不平、平面度失准、并无一定规律”的特征一致，因此按该条目的分析机制选定**一个待验证主方向**，不做多方向铺开。以下结论为待验证，不是已确认的唯一原因。

**假设（保留）**：未提供切削工况，按“连续端面切削中”假设；未提供冷热态，按“热机（连续加工一段时间后）”假设；未提供报警号与报警内容，报警表侧无对应条目可查，故不按报警表作答。

### 原因（待验证）
主方向：**主轴编码器及其连接环节的随机性失效**——编码器与机床固定部件松动、编码器内部脏污、连接编码器的传动带过松，或编码器与主轴连接传动比参数不符，使主轴与进给之间的插补关系出现随机偏差，反映到工件上就是端面接刀不平或平面度失准，且无一定规律。

依据：案例S073（`sqlite_fragment:204412`）在西门子系统数控车床上对“随机产生”的误差给出的原因分析为：主轴编码器不良、编码器内部太脏、编码器与机床固定部件松动、连接编码器的传动带过松；处理思路是先核对编码器与主轴连接传动比参数，再做软件与替换性测试以定位。本机虽表现为端面而非螺纹，但“无规律”这一随机性特征与该条目的判断逻辑一致，故以此为唯一主方向。

不选的方向（本路证据未指向，明确排除在主因之外）：热变形、砂轮/刀具不平衡、冷却液相关因素——观察中均未点到，不作为主方向；X轴爬行与润滑供油仅列为后续备选。

### 方法（仅针对上一节）
以下全部为**检查与测量**，不涉及拆卸、换件、定油压：

1. **参数核对（最先做）**：调出系统内编码器与主轴连接的传动比参数，与机床参数表/随机资料逐项比对，记录差异项。案例条目将这一步列为首查。
2. **紧固与污染目视记录**：停机、断电挂牌后，仅做目视与手感检查——编码器本体及支架与机床固定部件有无松动、连接编码器的传动带松紧是否明显偏松、编码器周围有无油污铁屑堆积；只记录状态，不动手拆解。
3. **信号观察**：在系统诊断页面观察主轴实际转速显示在恒速指令下是否跳变；有条件时用示波器看编码器A/B相波形有无丢脉冲、相位异常。记录跳变出现的时机（空转/切深变化时）。
4. **端面复现试验**：同一程序、同一切深、同一转速，连续车削3~5个端面，逐件记录平面度与接刀台阶的位置、深度是否随件变化（“随件变化”支持随机性来源，“固定位置”则指向X轴几何/间隙）；同时用百分表打X轴反向间隙与端面跳动，只记录实测读数，不预设合格限值。
5. **对照与分流**：若第1~3步任一项异常，主方向即被支持，下一步围绕该环节制定验证方案（验证方式待实测数据出来后再定，不在本路预设换件步骤）；若编码器链全部正常，再转入润滑供油链排查X轴低速爬行（导轨/丝杠供油是否到位、油品与脂种是否符合要求），届时另立待验证方向。

### 正确答案（原书）

检查分析：数控车床出现接刀不平等故障，常见的原因是导轨配合间隙失调、滑动导轨接触面不良、水平失准等。
故障处理：①故障诊断方法。检查导轨接触面，未发现接触不良现象；检查配合间隙，未发现间隙过大的现象；用电子水平仪检查机床的水平安装精度，发现机床失准。初步诊断由于机床失准，引起导轨变形发生弯曲，引起滑板运动精度误差，导致接刀不平的

### 判分

原因：no；处置：no

## 004｜CAK6163　CNC 型数控车床

**问题**：CAK6163　CNC 型数控车床，机床通电后，主轴运转正常。手动操作、返回参考点等动作都正确，程序也 可以空运行，但是不能执行车削加工程序。。最可能的原因是什么？应该怎么处置？请直接给出答案，不要向我提问。

### 原因（待验证）
主轴运转正常、手动操作和返回参考点正确、程序可空运行，说明基础主轴动作和回参链路基本正常。待验证主方向是：加工程序使用了车床 G12.1 的 X 轴直径/半径编程方式，或使用了主轴同期功能，而对应参数 Pr4020、Pr4021/Pr4022 的设置与程序要求不一致，导致实际车削加工程序段不能执行；空运行可能未暴露该条件。依据：NEAR 片段 sqlite_fragment:202210 说明 G12.1 的 X 轴编程方式由 Pr4020 决定（0：半径轴编程，1：直径轴编程），Pr4021 为第一组主轴同期功能基础主轴号码，Pr4022 为同期主轴号码，修改后需重新开机。该方向不是已确认唯一原因，需用报警号和参数值验证。

### 方法（仅针对上一节）
1. 先记录故障：执行车削加工程序时，记录数控系统显示的具体报警号/报警文本及停在哪一程序段。若报警号在报警表中查不到，明确写“查不到”，不要猜报警含义。
