日期：2026-11-03  
仓库提交：`1b8c527`（及本报告后续提交）  
远程：`https://gitee.com/maplegannache/sama2.0.git` · 分支 `master`

对照规格：桌面目录 `问题以及新的方案2/多跳图扩展检索树/多跳图扩展检索树规格.md`（规格与参考文献 PDF 目前在仓库外，本报告把已落地部分写进仓库）。

**结论先说：** 原先「五路不同入口 + 硬编码两跳 BM25」已改成「分温拉开第 0 步入口 → 图邻域 / 命中抽词做 beam 扩展 → 用带跳代价的折扣收益 $\Delta G$ 软停机」。出处核对、型号 / 油压硬拒绝、ReAct 工具循环未改。线上无向量时，路径分用 Jaccard + BM25 归一代替向量项；共现边尚未离线建表，邻域先用 `BRIDGES` + 机理词表。

---

## 1. 为什么要改

磨床问句常停在表面词。问「齿面粗糙度」，库里更有用的段落往往写「导轨爬行」「油品抗爬」。固定两跳容易在机理词上停住，跳数也不该由人手写死成 2。

白板思路是：在词 / 概念图上维护路径集合 $T$，对整条 $T$ 相对用户输入 $x$ 打分，用折扣和衡量还值不值得再跳。Best-of-N 五路若只改成稿温度、第 0 次检索仍撞同一批片段，后面的 $G$ 和评判只是在同一盆地里比稿。所以这次同时做了两件事：

1. 跳数由边际净收益决定，而不是业务上的 $H_{\max}=2$。
2. 分温必须作用在第 0 步入口查询，而不只作用在 ReAct 提议温度。

## 3. 第 0 步：分温进入不同检索路

### 3.1 问题

BM25 / 图扩展在**查询给定后**近似确定。同一 $t_0$ 进树，得到的是同一棵树。温度若只改成稿采样，检索第 0 步仍可能五路撞车。文献上，并行 agentic search 的瓶颈也常在第一轮查询冗余（DivInit）；分温能扩大可解子集（Temperature TTS），混合温度配置优于单一「最优纯温度」（Osca）。

### 3.2 做法

对用户输入 $x$ 先造候选池

$$
\mathcal{Q}_0=\mathrm{Core}(x)\cup\mathrm{Bridge}(x)\cup\{x\}\cup\mathrm{MechanismSlots}(x)
$$

槽位改写沿用原 `firstQueryForLane`（原句 / 桥接 / 机理 / 抗热相关）。每条候选有先验 $\mathrm{prior}(q)$；无向量时用规则分 + Jaccard。

第 $i$ 路温度沿用

$$
(\tau_i)=(0.35,\ 0.5,\ 0.85,\ 1.0,\ 0.95)
$$

默认 `treeEntryMode=softmax`：

$$
P_i(q)=\frac{\exp(\mathrm{prior}(q)/\tau_i)}{\sum_{q'}\exp(\mathrm{prior}(q')/\tau_i)}
$$

用 $\mathrm{seed}_i=S_0+i$ 可复现抽样。**$\tau\le 0.4$ 的低温路改为取 prior 的 argmax**（通常是原句），避免低温路偶发抽到机理词。跨路 Jaccard 过高则重抽，最多 `treeEntryRetry=3` 次，失败回退槽位改写。

备选 `mmr`：按 Maximal Marginal Relevance 从池中选 $N$ 条，再与路温按 prior 高低对齐。

同一 $\tau_i$ 传给该路 ReAct 的 `tauProp`，让「第 0 步敢换入口」和「敢改后续查询」共用温度轴。收束 / 评判仍用 $0.2$ / $0.1$。

### 3.3 行为直觉

| $\tau_i$ | 第 0 步更常落到 |
| ---: | --- |
| $0.35$ | 用户原句（argmax） |
| $0.5$ | 原句附近或轻桥接 |
| $0.85$–$1.0$ | 机理槽、桥接词、抗热相关改写 |

进 `ExpandTree` 之后，线上默认不再用温度搅每一跳邻域；树上按分数取 Top-$K$，用 $\Delta G$ 停机。

## 4. 树上：beam、打分与 $\Delta G$ 软停机

### 4.1 状态与扩展

路径 $\pi$ 维护词集合 $T$、片段集合 $D$、相关分 $S$、累计回报 $G$。每跳候选来自：

- 静态图邻域：`BRIDGES` 机理边 + 机理词近邻（`kgNeighbors`）
- 当前命中片段里抽出的机理 / 新词

宽度 $K\in\{3,5,7\}$，配置名 `treeBeamK`，默认 $3$。词集合 Jaccard $>0.8$ 的近重复路径只留分高的一条。

### 4.2 路径分（暂无向量）

规格写混合向量 + 词法。当前仓库无嵌入服务，实现为：

$$
s(x,T)=\alpha\,s_{\mathrm{Jaccard}}(x,\mathrm{text}(T))+(1-\alpha)\,s_{\mathrm{lex}}^{\mathrm{norm}}
$$

$s_{\mathrm{lex}}^{\mathrm{norm}}$ 由命中 BM25 原始分经 $r/(r+5)$ 压到 $(0,1)$。$\alpha$ 默认 $0.5$（`treeAlpha`）。

### 4.3 回报与停机

$$
G=\sum_n\bigl(\gamma^{n-1}S_n-c_n\bigr),\qquad c_n=\lambda_{\mathrm{hop}}\gamma^{n-1}
$$

边际净收益（增量形式）：

$$
\Delta G_n=\gamma^{n-1}(S_n-S_{n-1})_{+}-c_n
$$

**主停机：** $\Delta G_n\le 0$（再跳买不回代价）。  
默认 $\gamma=0.6$、$\lambda_{\mathrm{hop}}=0.15$（`treeGamma` / `treeHopCost`）。

保险丝（不是业务上界）：检索次数 `treeRetBudget=12`、跳数 `treeHopFuse=16`、无新文档、查询 Jaccard $\ge 0.85$。旧配置项 `treeHops` 仍保留兼容，业务停机不依赖它。

返回 $G$ 最大路径上的片段（去重后最多 4 条写入观察）。观察文案含入口、路径词、$G$、路温。

## 5. 默认超参一览

| 配置 | 默认 | 含义 |
| --- | ---: | --- |
| `laneTemps` | `[0.35,0.5,0.85,1.0,0.95]` | 路温；入口 + 提议共用 |
| `treeEntryMode` | `softmax` | 入口模式；可选 `mmr` |
| `treeBeamK` | `3` | beam 宽度（仅 $3/5/7$） |
| `treeGamma` | `0.6` | 折扣 |
| `treeHopCost` | `0.15` | 每跳代价 $\lambda_{\mathrm{hop}}$ |
| `treeAlpha` | `0.5` | Jaccard 与词法混合 |

| `treeHopFuse` | `16` | 跳数事故保险丝 |
| `treeEntryRetry` | `3` | 入口撞车重抽次数 |
| `treePriorBeta` | `0.5` | prior 中词法 / 规则混合 |
| `treeMmrLambda` | `0.5` | 仅 MMR 模式 |

环境变量可选：`SAMA2_TREE`、`SAMA2_TREE_ENTRY`、`SAMA2_TREE_BEAM_K`。

## 8. 和 Best-of-N 的关系（一句话）

分温 Softmax 入口 ≈ 多起点；每路树上的 beam + $\Delta G$ ≈ 各盆地里的局部搜索。这不是「少算力就保证全局最值」，而是在固定五路预算下，让证据与查法覆盖更宽，再交给原有的加权评判与出处核对选一份交付。
