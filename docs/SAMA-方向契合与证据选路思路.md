# 方向契合与证据选路：把检索结果真正用进推理

留出集上 0 全中，不是因为模型不会推理，也不是因为检索树必须硬走两跳。问题更窄：**库里已经给出的近邻资料，没有压过模型脑子里的磨床通识**。结果就是 C08-29 一类题会滑到冷却 / 砂轮 / 热变形，而不是沿着本路观察里最贴现象的机理往下走。

本文只讲改法，不改代码。参考文献 PDF 在 `docs/文献-方向契合与证据选路/`。

逐步公式（入口 Softmax、$s_{\mathrm{vec}}$、$\Delta G$ 停机、PMI、片段分级、方向卡、评判封顶）写在 [多跳图扩展检索树落地报告](./多跳图扩展检索树落地报告.md) 第 3–5 节和第 8 节，并逐条对应本文引用的文献。

---

## 1. 要解决的到底是哪一步

打分对象不是复述被删掉的金标答案，而是：**有没有找到当前库里最合适的资料，再从这份资料推出一个可继续往下走的主方向**。留出集本来就没有标准答案；正控 31/32/33 才用来检验「库里还有原案例时，链能不能接到具体件号」。

当前运行时把这两件事搅在一起了。

| 环节 | 现在实际在做什么 | 对方向契合的伤害 |
| --- | --- | --- |
| 检索树 | ΔG 决定跳数，近邻片段已经进观察 | 检索本身不是主因 |
| 系统提示 | 「独立理解」「查不查资料由你自己决定」 | 允许无视观察，回到参数化通识 |
| 无案例横幅 | 「以下为候选方向」 | 被理解成可以列教科书清单 |
| 树文本位置 | 整段塞进 `notes`，和后续工具观察混在一起 | 最好的片段不在开头，容易被淹没 |
| 主控简报 | 先给 3～4 条待验证假设 | 通识假设可能先于证据进入各路 |
| 评判 | accuracy 30% + completeness 15%；`mechanism` 层不改名次 | 列得全、写得长的路更容易赢 |

C08-29 的失败形态正好对应文献里的 **知识冲突**：上下文里有近邻案例，参数记忆里有「磨削精度差 → 热变形 / 砂轮」，模型选了后者。

## 2. 文献怎么对上 SAMA

十篇都下到了本地文件夹，用法不是照搬论文系统，而是各借一块接到现有 ReAct 环上。

### 2.1 知识冲突：为什么通识会赢

**Longpre et al., 2021, Entity-Based Knowledge Conflicts in Question Answering**  
`Longpre-2021-Knowledge-Conflicts.pdf`

结论：当检索到的上下文和模型参数记忆冲突时，模型经常坚持参数记忆。SAMA 的冲突不是实体替换实验那种硬对抗，而是更日常的版本：观察里是某台机床的近邻机理，参数里是通用磨床故障树。提示词还写了「按你自己的理解判断」，等于给参数记忆开了绿灯。

落到 SAMA：主方向不允许写成观察里没出现过的通识条目。热变形、砂轮不平衡、冷却液，只有 SUPPORT 片段点到它们时才能当主方向。

### 2.2 先评检索，再生成

**Asai et al., 2023, Self-RAG**  
`Asai-2023-Self-RAG.pdf`

模型自己决定要不要检索，并给生成打「是否被证据支持」的critique。SAMA 已经有工具环，缺的是 critique：当前观察能不能支撑即将写下的主方向。

**Yan et al., 2024, CRAG**  
`Yan-2024-CRAG.pdf`

检索结果先过评估器，分成正确 / 模糊 / 不正确，不正确就纠正或丢掉。SAMA 的树检索经常是「近邻但不是本机」。现在整段当资料用，模糊和无关被当成已证实。需要一个便宜的片段分级，而不是把 hop 文本原样喂给求解器。

### 2.3 证据在上下文里的位置

**Liu et al., 2023, Lost in the Middle**  
`Liu-2023-Lost-in-the-Middle.pdf`

长上下文里，两头比中间更被用到。树文本现在作为第 0 步观察整段注入，后面再叠工具返回，真正有用的近邻句很容易掉到中间。要把 SUPPORT 片段提到观察区最前，IRRELEVANT 放到末尾或丢掉。

### 2.4 必须从文档里讲出推理，而不是「看过资料再自由发挥」

**Wei et al., 2025, InstructRAG**  
`Wei-2025-InstructRAG.pdf`

显式训练 / 指令模型：**先说明答案如何从检索文档推出来**。SAMA 不需要微调，只要在成稿前强制一张「方向卡」：主方向、支撑观察 id、一句话理由。

**Li et al., 2025, Search-o1**  
`Li-2025-Search-o1.pdf`

Reason-in-Documents：对搜到的文档先做针对性精读，再接入推理。对应 SAMA 就是：不要让五路直接对着 3k 字树文本写维修方案，先压缩成几条带 obsId 的证据卡。

### 2.5 引用是否真的支撑结论

**Gao et al., 2023, ALCE**  
`Gao-2023-ALCE-Citations.pdf`

评的是「这句话能不能被所引段落支持」，不是「像不像标准答案」。这就是留出集该用的尺度：方向契合 = 主方向能回溯到本路观察，而不是命中已删除的金标件号。

### 2.6 不确定再查，而不是固定跳数

**Jiang et al., 2023, FLARE**  
`Jiang-2023-FLARE.pdf`

生成时低置信才触发下一次检索。这和 ΔG 软停机是同一类思想：收益不够就停。方向卡如果写不出 SUPPORT，允许再查一次「主方向关键词」，这不是硬两跳，是不确定驱动的补检。

### 2.7 过程分，而不是只看终稿漂亮

**Lightman et al., 2023, Let’s Verify Step by Step**  
`Lightman-2023-Verify-Step-by-Step.pdf`

过程监督：中间步骤对了，终局才稳。SAMA 现在只给终稿加权；`mechanism` 层明确「不改变加权名次」。应该给方向卡单独打过程分，并让它进入冠军选择。

### 2.8 我们其实已经有 ReAct，缺的是批评器

**Yao et al., 2022, ReAct**  
`Yao-2022-ReAct.pdf`

Thought → Act → Observation 已经在 `reactLoop.mjs` 里。缺的是 Observation 之后、Final 之前的那一刀：这批观察支持什么方向、不支持什么方向。

## 3. 改法：四段，全部接在现有环上

不换模型，不恢复 Electron，不改 ΔG 公式，不把 hop 写成常数。检索树继续按收益停机；改的是 **树输出之后怎么用**。

```
故障原文
    │
    ▼
检索树（现有，ΔG 决定跳数）
    │
    ▼
① 片段分级 CRAG/Self-RAG
    SUPPORT 提前，IRRELEVANT 降权或丢弃
    │
    ▼
② 方向卡 InstructRAG / Search-o1
    主方向 + obsId + 一句话
    通识条目无 SUPPORT 则禁止做主方向
    │
    ├─ 支撑不足 ─► FLARE 式补检一次（仍由 ΔG/收益约束）
    │
    ▼
③ 各路按方向卡写排查方案（现有 ReAct）
    │
    ▼
④ 评判：方向契合进 accuracy，mechanism 改名次
    ALCE：无 obsId 的主因封顶
```

### 3.1 片段分级，在进求解器之前

树文本进入 `reactLoop` 之前（或刚注入、尚未调用模型时），按**用户现象**给每条 chunk 打三档：

- `SUPPORT`：片段里的机理 / 部位 / 工况和当前现象对得上
- `NEAR`：同子系统或近邻案例，可作参考，不能当本机结论
- `IRRELEVANT`：通识段落、无关机型、只共享了「磨削」「振动」这类泛词

程序侧先做廉价过滤（子系统、家族、已有 term-graph 边），过不掉的再让小模型打标签，避免每条都走一次大模型。

注入格式建议：

```
【本路可用证据】
[SUPPORT] sqlite_xxx  原文要点…
[NEAR]     sqlite_yyy  仅近邻，不得写成已确认

【未采用】
[IRRELEVANT] …
```

`SUPPORT` 必须出现在观察区最前面。这是 Lost-in-the-Middle 的直接对策。

没有 `SUPPORT` 时不要假装有案例。横幅改成：

> 本地无对得上的本机案例。下面只用近邻资料选一个待验证主方向，不要展开成通用磨床清单。

现在的 `NO_CASE_BANNER`（「以下为候选方向」）会诱导列冷却、砂轮、热变形。横幅要限制**数量和来源**，不是放开清单。

### 3.2 方向卡：先承诺主方向，再写方案

在 `mustFinish` 之前加一个强制 JSON，不写维修步骤：

```json
{
  "main_direction": "进给丝杠预紧/反向间隙，而不是热变形",
  "support_obs": ["sub0-tree", "sqlite_..."],
  "from_observation": "观察里出现丝杠/反向差动，没有出现热机温升曲线",
  "next_check": "冷热态各打一次反向差",
  "alternatives": [
    { "direction": "头架轴承预载", "support_obs": ["..."] }
  ]
}
```

硬规则：

1. `main_direction` 必须带至少一条 `SUPPORT` 或明确标成 `NEAR`。
2. 观察未点名的通识机理，不能当 `main_direction`。
3. `alternatives` 最多两条，同样要有观察 id。
4. 这不是抄金标。留出集没有 46# 也可以承诺「沿丝杠方向查」，因为那是当前库里最贴的资料。

提示词要改掉两句：

- 删「查不查资料、先看什么，都由你自己决定」
- 改成「先读本路【可用证据】，主方向必须从中选出；证据不够就写下一步要测什么，禁止回退到通用故障清单」

主控简报（`brief.mjs`）也要后置：先有分级证据，再生成假设。现在简报在检索使用之前就把「待验证假设」发给各路，通识会污染五路采样。

### 3.3 不确定才补检，仍然不是硬两跳

方向卡若 `support_obs` 为空，或分级全是 `IRRELEVANT`：

- 用「现象 + 当前最像的一个词」再检索一次
- 新片段仍走 3.1 分级
- 是否采纳继续看 ΔG：没有正收益就停，承认「只能给待测方向」

这是 FLARE，不是把 `hopsUsed>=2` 写回代码。

### 3.4 评判按方向契合，而不是按清单完整

改 `judge.mjs` / `config.mjs` / `accuracyJudge.mjs` 三处语义，不必先改权重数字：

**accuracy（故障定位准确性）改定义为方向契合**

- 高分：主方向能从本路 `SUPPORT`/`NEAR` 观察推出来，且没有把用户没提、观察也没有的故障写成主因
- 低分：主因来自通识清单，观察对不上
- 封顶规则（ALCE）：成稿主因没有 obsId / chunk id，accuracy 不超过中档

**completeness 不再奖励「把冷却砂轮热变形都写一遍」**

- 高分：主方向的验证步骤闭环（测什么、什么结果排除、下一步去哪）
- 低分：条目很多但都没有观察支撑

**mechanism 必须改名次**

现在写明「三层参考分，不改变加权名次」，所以方向错、清单全的路仍可凭 completeness / feasibility 赢。至少把 `mechanism` 并进 accuracy，或作为冠军的否决项：mechanism 明显低于阈值不得中选。

**过程分**

方向卡单独 0/1/2：无支撑 / 近邻支撑 / 直接支撑。和终稿 accuracy 一起看。正控 31/32/33 应拿到 2；留出集拿 1 也算方向对，不必拿 2。

## 4. 和「找最合适的数据再推理」怎么对齐

留出集没有金标，正确行为是：

1. 在可见库里找最像的近邻（检索树已经在做）
2. 承认它不是本机案例（横幅）
3. **仍然承诺一个主方向**，因为后面的逻辑链需要一个入口
4. 把通识条目降成「仅当观察提到才保留」

错误行为是现在的：检索了，但成稿从参数记忆重写一棵磨床故障树。那不是推理能力差，是证据没用上。

正控 31/32/33 用来回答另一个问题：库里还有原案例时，方向卡是否引用了 curated 片段，后续步骤是否接到 6411 / N32 / 8# 这类具体物。两跳有没有用，看这个，不看留出集全中率。

## 5. 建议落地顺序

只改提示和评判，也能先验证假设；分级器可以先规则后模型。

1. **提示 + 横幅 + 简报后置**  
   改 `prompts.mjs`、`grounding.mjs` 的 `NO_CASE_BANNER`、`brief.mjs` 调用时机。代价最低，直接打知识冲突。

2. **观察区重排**  
   树文本拆成 SUPPORT / NEAR / IRRELEVANT，SUPPORT 置顶。对应 Lost-in-the-Middle。可先用规则（家族、子系统、term-graph），不接新模型。

3. **方向卡 JSON**  
   收束前强制输出。无卡或无 obsId 的路，评判直接降 accuracy。

4. **评判语义**  
   accuracy = 方向契合；completeness 不奖清单；mechanism 影响冠军。`accuracyJudge` 的审计提示同步改，避免附录和冠军标准打架。

5. **FLARE 补检**  
   只在方向卡支撑为空时触发。继续受 ΔG 约束。

验收不要再用「留出集是否写出已删除金标」：

- 留出集：主方向是否落在近邻资料的机理上（方向契合），通识主因应下降
- 正控 31/32/33：方向卡是否引用在库案例，具体件号/措施是否出现
- 过程：方向卡 0/1/2 分布，SUPPORT 片段是否出现在观察区前 20%

---

## 6. 不做什么

- 不把 hop 写成 2，不改 ΔG 公式来「保证多跳」
- 不把金标答案写回提示词或评判清单
- 不换基座模型当第一手段；先把证据选路和评判目标改对
- 不在没有 SUPPORT 时禁止输出——仍要给现场一个待测主方向，只是禁止展开成通识目录
