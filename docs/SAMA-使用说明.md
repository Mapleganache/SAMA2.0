# SAMA 2.0 使用说明

日期：2026-11-03  
适用代码：仓库 `D:\SAMA\SAMA` 内的 `sama2.0/`  
配套：[Agent 结构报告书](./SAMA-Agent结构报告书.md) · [算法数学推导](./SAMA-算法数学推导.md) · [数据库说明书](./SAMA-数据库说明书.md)

本说明给**现场使用者和本机开发者**。读完应能：装起来、问对题、看懂第一名 / 第二名、知道什么时候系统在假设、什么时候答案不能当本机指令。

---

## 1. 它做什么、不做什么

SAMA 根据磨床故障描述决定三条路之一：先追问、直接解释、或开多路排查后交出两份候选方案。方案里的数值必须能在本轮资料或你原文里找到。数据库是历史原文参考，**不是已经批准的本机维修规程**。

不要用它做：电气 LAD 逐点核验、把别的机床油压抄到本机、当唯一施工依据、代替现场测量。

---

## 2. 安装

需要 Git、Node.js **22.13 或更高**、npm，磁盘建议预留 3 GB。本仓库可用 `D:\SAMA\_node\node.exe`。

```powershell
git clone https://gitee.com/maplegannache/sama2.0.git
cd sama2.0/sama2.0
npm ci
npm test
npm start
```

已有仓库：先在仓库根目录 `git pull --ff-only`，再进内部 `sama2.0` 执行上面后三步。**不要在仓库根目录跑 `npm ci`**（根目录不是旧 Electron 应用）。

`npm ci` 会从 Git 里的压缩分片还原 SQLite，并校验 SHA-256。不需要 Python，不需要 8765 端口，不需要抄别人电脑的绝对路径。

`npm test` 不调真实模型、不需要 API Key。通过只说明安装、检索、引用、门控和流程图接线正常，**不代表维修答案准确**。

浏览器打开 <http://127.0.0.1:3920>。PowerShell 若改端口：

```powershell
$env:SAMA2_PORT='3921'
npm start
```

## 3. 配置密钥

真正生成回答需要 DeepSeek 兼容接口的 Key。三种来源，后者覆盖前者：页面本次填写 → 环境变量 → `sama2.0/settings.json`。

复制示例后填写，**不要提交密钥**：

```powershell
copy settings.example.json settings.json
```

```json
{
  "baseUrl": "https://api.deepseek.com",
  "model": "deepseek-chat",
  "judgeModel": "",
  "apiKey": "你的密钥"
}
```

`judgeModel` 留空则评判、分类、简报、审计与生成用同一模型。环境变量：`SAMA2_API_KEY`、`SAMA2_BASE_URL`、`SAMA2_MODEL`、`SAMA2_JUDGE_MODEL`。

页面上的 Key 只存在这台浏览器的 `localStorage`，刷新还在，换电脑没有。

## 4. 页面怎么用

### 4.1 字段

| 控件 | 含义 |
| --- | --- |
| API Key / 接口 / 模型 / 评判模型 | 本次请求覆盖本地设置 |
| 每路最多轮次 | 默认 8，最大 50。越大越慢越贵 |
| 强制走五路 | 跳过复杂度判断，仍先检查必填项 |
| 作者开关 | 显示流程、五路思考、停因、第一名审计 |
| 允许网页搜索 | 把 `web_search` 加入工具表；本地未命中时可能自动联网 |

### 4.2 怎样描述故障（推荐）

一次写清四件事，系统才少追问：

1. **机型或家族**：STUDER、高桥、MIKROSA、外圆磨床、数控磨床… 只写「磨床」不够。
2. **现象**：发热、振动、异响、齿面粗糙度、爬行、抱轴、漏油、报警号。
3. **工况**：空载，还是正在磨削。
4. **热态**：刚开机冷机，还是已运转热机。

好例子：

> 数控磨床，磨削中，热机，加工齿轮时齿面粗糙度始终达不到工艺要求，电气和机械多次检修都没有改善。最可能的原因是什么？

> 外圆磨床主轴发热并且振动，空载，刚开机。

差例子：「磨床有问题」「主轴不好了」——会先问，不给步骤。

问概念可以直接问：「什么是磨床静压轴承」。不要和「怎么办 / 如何修」混在一句里。

### 4.3 追问时怎么补

黄色框出现后，输入框变成「补充回答」。**只写补充**，不要重贴整段原题。例如：「刚开机的冷机，现象出现在空载」。原题留在会话里。刷新页面会话清空，需要从头再问。

同一项最多问两次；之后若仍缺工况 / 热态，系统会按「磨削中 / 热机」假设并在答案开头写明。方案里这些是假设，不是你已经测过的事实。

若写错工况，在补充里用「更正为」：只保留最后一个「更正为」后面的冷热 / 空载标记。

### 4.4 怎么读结果

**简单问题**：一段解释。若有未在资料里出现的扭矩 / 间隙 / 压力，前面会警告不能当事实。

**需要补充**：只有问题列表，没有维修步骤。

**复杂故障 / 边界题**：

1. 上方两张卡：**第一名（绿框，推荐）**和**第二名（蓝框）**。每张有准确性 / 安全 / 可行 / 完整 / 简洁和加权分。
2. 下方完整文本同样两份，另有「评分对照」表。
3. 系统推荐第一名，**请你对照评分和现场情况自选**。
4. 「审计附录」只针对第一名，不改名次。
5. 若出现「本地无对得上的本机案例」：主方向只是待验证，不要当成已确认唯一原因。
6. 「按假设作答」：答案用了默认工况 / 热态 / 机型未知约束。
7. 「待确认问题」：有一路还在问，但已经有可评分的成稿。

作者开关打开后：复杂度来源、提取的事实、流程图、每一路思考和工具观察、第一名的准确性 / 可信度。

### 4.5 什么时候结果不可信

- 方案引用了观察里没有的 `sqlite_*` 或具体 MPa / mm（程序应挡掉；若你在作者视图看到被拒方案，不要用）。
- 把冷却液 / 砂轮 / 热变形写成主因，但【可用证据】里没有对应片段。
- 问的是留出集已删案例：库里没有那条金标，跳多少跳都不会「全中」。
- 电路 / LAD / 急停 / 某未建档型号的专属报警：库会拒绝或只给限制说明。
- 问「油压应该设多少确定值」且无本机已核验阈值：不会给数。

## 6. 常用环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `SAMA2_API_KEY` | 空 | 密钥 |
| `SAMA2_MODEL` / `SAMA2_JUDGE_MODEL` | deepseek-chat | 生成 / 评判 |
| `SAMA2_MAX_STEP` | 8 | 每路轮次 |
| `SAMA2_SEED_BASE` | 1000 | 五路种子起点 |
| `SAMA2_FORCE_MULTI` | 关 | 强制五路 |
| `SAMA2_ALLOW_WEB` | 关 | 网页搜索 |
| `SAMA2_GATE` | soft | `hard` 则缺项必问 |
| `SAMA2_TREE` | 开 | `0` 关闭检索树 |
| `SAMA2_EMBED` | hash | `jaccard` 关闭稀疏余弦 |
| `SAMA2_TREE_ENTRY` | softmax | `mmr` 改入口 |
| `SAMA2_SQLITE_PATH` | `data/sama_full.sqlite` | 自有库 |
| `SAMA2_SQLITE_MODE` | 配置文件 | production / reviewed / reference / catalog |
| `SAMA2_SKIP_DB_PREPARE` | 关 | `npm ci` 不还原库 |
| `SAMA2_PORT` | 3920 | 页面端口 |
| `SAMA2_BRIEF` | 开 | 主控简报 |

检索树跳代价默认 0.15，不要为了「多跳」改成 0。

PowerShell 赋值：`$env:SAMA2_GATE='hard'`。

## 7. 测试与重建图

```powershell
npm test
npm run test:db
npm run test:core
npm run build:graph
npm run smoke:lanes
```

`build:graph` 从当前 SQLite 重建 `sama-sqlite/term-graph.json`。换库或更新分片后应重跑。`smoke:lanes` 看五路入口是否错开（需要库）。

开发用假模型走流程：`node test-flow.mjs`（不消耗 Key）。

## 8. 现场提问清单（打印用）

问诊断题之前尽量收集：

- [ ] 磨床家族或型号
- [ ] 至少一个可观察现象（不要只说「不好」）
- [ ] 空载还是磨削
- [ ] 冷机还是热机
- [ ] 是否已换件 / 已检修仍不好
- [ ] 你原文里已经有的读数（间隙、压力、温度），系统只会记录原文里有的数
- [ ] 不能停机、不能拆、没有备件等约束

拿到两份方案之后：

- [ ] 看第一名主方向是否来自资料里的 SUPPORT/NEAR，而不是通用清单
- [ ] 看第二名是否更贴你现场的结构（导轨 / 主轴 / 顶尖…）
- [ ] 把「待验证」当排查顺序，不要当已经拆过的结论
- [ ] 油品、间隙、压力以本机手册和实测为准

## 9. 故障排查（软件本身）

| 现象 | 处理 |
| --- | --- |
| `未配置 API Key` | 填页面 Key 或 `settings.json` |
| 端口占用 | 换 `SAMA2_PORT` 或结束旧 `node server.mjs` |
| `npm ci` 说已有库指纹不同 | 先备份再移走 `data/sama_full.sqlite`，或 `SAMA2_SKIP_DB_PREPARE=1` 并指定自有库 |
| 分片校验失败 | 重新 `git pull`，不要手改 `database-pack/` |
| 一直追问 | 补四项；或已补过一轮后应进入评分。仍死循环再查是否误开硬门控 |
| 五路入口几乎相同 | 确认 `SAMA2_TREE` 未关；看作者视图里「本路第一次查询词」 |
| 只有一份方案 | 只有一路通过出处核对，属正常 |
| 中文界面公式 | 本使用说明无公式；算法文档用 `$...$` |

## 10. 和旧说明的差异

- 复杂故障不再「只交付综合分最高的一份」，而是前两名 + 评分。
- SQLite 默认开启，不必再起 MTKB 的 8765 服务。
- 检索树和证据分级在模型思考之前已经跑完。
- 短版架构页 `/report` 仍可用；完整结构以 `docs/SAMA-Agent结构报告书.md` 为准。
