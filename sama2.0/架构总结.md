# SAMA 2.0 架构总结

这份说明写的是现在这套磨床维修程序实际在跑的结构。五路求解没有预先分配「根因、现场、风险、步骤、工单」这类分析倾向。编号只用来区分是哪一路。

本地页面在 `http://127.0.0.1:3920`。作者开关打开时能看到分类、事实、五路方案、加权分、准确性与可信度、流程走向，以及每一步的思考、工具、参数和观察。开关关闭时只显示给用户的回答。

## 1. 总流程

用户故障原文进入 Main。Main 先抽事实，再判断简单还是复杂。

- 简单：Main 自己查资料后直接回答，不启动五路。
- 复杂：同一份完整问题同时交给 5 路。每路各自做 ReAct，互相看不到。
- 五路都结束后，加权评判和准确性专评同时进行。两者不改写方案，也不改对方的分数。
- 若两者选出的方案不同，两份结果都保留，回答里会写明。

页面上的「强制多路」或环境变量 `SAMA2_FORCE_MULTI=1` 会跳过复杂度判断，直接走五路、加权评判和准确性专评。

## 2. 各 Agent 做什么

| 角色 | 任务 |
| --- | --- |
| Main | 抽事实；按硬规则分类，边界才问模型；简单题直接作答 |
| 第 1–5 路 | 同一提示、同一套工具，按自己的理解查资料并写出维修方案 |
| 加权评判 | 只给五项分数。程序自己算总分并选最高分方案 |
| 准确性专评 | 只评哪一份最对准用户描述的现象，以及这份判断有多可追溯。不替换加权评判 |

五路的提示相同：独立阅读完整故障，自己决定查不查、先看什么、方案怎么写。没有实测或资料原文时，不编造扭矩、间隙、压力、油压、精度和备件规格。

## 3. 工具

五路都能用下面四个工具，没有哪一路被指定只用某一个。

| 工具 | 作用 |
| --- | --- |
| `search_mechanical` | 在本地 `knowledge/*.md` 里检索机械资料 |
| `search_knowledge` | 同一批资料的检索，简单题也会用 |
| `lookup_baseline` | 查本地排查顺序模板，例如主轴、砂轮、头架尾架、导轮、液压润滑、冷却、进给、工作台 |
| `lookup_grind_dialect` | 识别机床家族（斯图特、高桥、米克罗萨、无心、内圆、平面、外圆）。它不是实测读数 |

不认识的工具会被拒绝。

## 4. 简单 / 复杂

硬规则先于模型。复杂优先于简单。

判成复杂：

- 同时出现至少两个症状组（热、振动、噪声、精度、运动、流体、报警）
- 间歇性
- 已经处理过但故障还在
- 需要同时具备机型、工况和历史才能判断

判成简单：概念解释、参数或保养查询、短的日常保养。

只剩边界（例如只有「主轴发热」）时，才让模型输出 `{"level","reason"}`。分类失败就按复杂处理。没有 API Key 时直接报错，不会悄悄降成简单题。

## 5. 五路 ReAct

每一路循环是：思考 → 调用工具 → 读观察，或思考后直接给出最终方案。

步数在每次思考开始时加 1。记当前步数为 \(t\)，上限为 \(T\)：

\[
t \leftarrow t + 1, \qquad \text{当 } t \ge T \text{ 时不再调用工具}
\]

调试默认 \(T = 8\)。硬上限是 50，小于 1 或大于 50 都会被夹回这个区间。单路默认超时 180 秒。若剩余时间不足 8 秒，不再请求模型，直接把已有笔记收成方案。

五路同时跑，默认并发 5。第 \(i\) 路（\(i = 0,1,2,3,4\)）延后 \(0.4i\) 秒再开始，用来错开请求。某一路失败会写成「方案生成失败」，不打断其余路。五路都因没有 API Key 失败时，整次请求报错。

## 6. 加权分

模型只打五项 0 到 10 的分。程序负责裁剪、加权和选优。

记某一项原始分为 \(x\)，先裁到 \([0,10]\)：

\[
s = \operatorname{clip}(x, 0, 10) = \min(10,\max(0,x))
\]

非数字也按这个区间处理。五项权重相加为 1，加权总分最高仍是 10：

\[
S = 0.30\,A + 0.25\,B + 0.20\,C + 0.15\,D + 0.10\,E
\]

| 符号 | 维度 | 权重 | 模型在看什么 |
| --- | --- | --- | --- |
| \(A\) | 准确性 / 定位 | 0.30 | 方案是否对准用户写出的现象 |
| \(B\) | 安全性 | 0.25 | 是否先做能量隔离、砂轮防护，是否拦住带电或带压拆卸 |
| \(C\) | 现场可行性 | 0.20 | 只有这个维度名称，提示里没有另列检查清单 |
| \(D\) | 完整性 | 0.15 | 方案是否把该交代的判断和步骤写全 |
| \(E\) | 简洁 | 0.10 | 是否避免无关铺陈 |

「方案生成失败」的路不参与评选。其余路按下面的顺序比较，前一项相同才看后一项：

\[
(S,\; B,\; A)
\]

也就是总分高者胜；总分相同，安全性更高者胜；再相同，定位准确性更高者胜。评判模型失败时，程序在已完成的方案里按同一规则兜底，并在结果里注明。

## 7. 准确性专评

这一路单独打两分，每分也是 0 到 10，同样先做 \(\operatorname{clip}(\cdot,0,10)\)。

- 准确性 \(a\)：是否对准用户写出的现象；原因是否从这些现象推出来；没有写到的故障不能当成已确认。
- 可信度 \(c\)：判断能否追溯到用户原文或写明的检查。凭空写出的扭矩、间隙、压力、精度会拉低可信度。没有实测时，「待测 / 先排查」可以高；把猜测写成结论必须低。

程序不采用模型自己点名的优胜编号，只按准确性、再按可信度排序：

\[
(a,\; c)
\]

最高的一组就是准确性专评选出的方案。它可以和加权总分选出的方案不是同一份。

## 8. 资料检索分

本地资料很少，检索分只决定哪几段笔记排在前面，不是维修结论的分数。

查询先取长度至少为 2 的词，再取连续二字片段，合计最多 20 个词。文档对每个命中词加分：

\[
\operatorname{score}(d) = \sum_{w \in W} \mathbf{1}[w \in d] \cdot
\begin{cases}
2 & |w| > 1 \\
1 & |w| = 1
\end{cases}
\]

若指定了子系统但没有专文，就退回全文检索，并在结果里说明。没有命中时明确告诉模型：不要把没查到的内容写成手册条款或具体数值。

## 9. 作者开关里能看到什么

- 简单还是复杂，以及原因和依据来自硬规则还是模型
- 抽出的事实
- 流程走向
- 每一路每一步的思考、工具名、参数、观察或最终方案
- 加权五项分和总分
- 准确性、可信度对照表，最高的一行会标出

## 10. 读结果时要记住的界限

五路提示相同，不保证五路会走出不同的查法。分数接近时，第一名只表示这次加权或准确性排序更高，不等于现场已经验证。

本地资料是六篇短笔记，不是机床手册。具体扭矩、间隙、压力和精度必须来自实测或资料原文。
