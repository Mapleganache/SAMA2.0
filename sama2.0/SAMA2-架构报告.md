# SAMA 2.0 架构

这份说明对应当前在跑的磨床维修程序，代码在 `electron/services/sama2.0`。本地页面是 `http://127.0.0.1:3920`，本报告由同一服务的 `/report` 渲染。旧的电气、G 代码和聊天窗口不在这套流程里。

## 1. 用什么搭

主流程是一张 LangGraph 状态图，编译后的名字是 `diagnosisGraph`。模型调用走 LangChain 的 `ChatOpenAI`，对接当前的 DeepSeek 兼容接口。工具用 LangChain 的 `tool()` 登记，并带上参数约束。

每一路求解是第二张图：思考、执行工具、再思考，写成方案后才收束。停机条件、出处核对和加权分由程序执行。模型可以打分，不能自己指定哪一路中选。

五路使用同一份提示和同一套工具，没有预先分配的专家角色。编号 `sub0` 到 `sub4` 只用来区分第 1 路到第 5 路。

## 2. 一次提问怎么走

用户文字先和本轮补充拼在一起。页面把原题和补充留在内存里，刷新即清空，不写入数据库。句子里出现「更正为」时，工况和热态只保留最后一个标记后面的内容。

入口节点提取事实，再用硬规则看复杂度。后面只走四条边之一。

### 一次答复

概念、参数、短保养，并且没有打开「强制走五路」。程序检索后回答一次，再核对扭矩、间隙、压力。对不上观察的数字会加上警告，文字仍然交出去。

### 只提问

诊断题缺少下面四项中的任何一项时，本轮不检索、不采样、不写维修步骤。

| 字段 | 要问清什么 |
| --- | --- |
| 机型 | 磨床家族或型号。单独的「磨床」不算 |
| 现象 | 至少一种，例如发热、振动、异响、超差、爬行、漏油、报警 |
| 工况 | 空载，还是正在磨削 |
| 热态 | 刚开机的冷机，还是已经运转过的热机 |

四项使用固定问法。空载和磨削同时出现，或冷机和热机同时出现，就继续问，不让后一句盖掉前一句。

### 分类模型

硬规则说不准、四项又已经齐了，才调用分类器。分类器判成简单，就走一次答复。否则当作边界题。分类器失败时按复杂题处理。没有 API Key 会直接报错。

### 采样

硬规则已经是复杂题，或者勾了强制五路并且四项齐全。强制五路不会跳过缺项检查。

## 3. 复杂度

硬规则先看，复杂优先于简单。

- 同时出现两类以上现象：发热、振动、异响、精度、运动、液压润滑、报警。
- 偶发或间歇，不能按一次复现下结论。
- 已经更换、检查或排查过，问题仍在。
- 明确要求结合型号和历史维修记录。

下面这些是简单题：概念或名词解释；参数、保养周期、备件查询；不超过 36 字、没有故障现象的日常保养。其余留给分类模型。

## 4. 采样怎么展开

复杂题一次开满 5 路。提示词相同，工具相同。差别只有种子：默认从 1000 起，每一路加上自己的序号。提议时温度 0.7，被迫写最终方案时温度 0.2。

边界题先只开第 1 路。这一路没有向用户提问、也没有生成失败时，做一次安全抽查，并核对出处。出现下面任一情况，才在第二波补上其余 4 路：

- 方案里写了「信息不足」
- 安全分低于 6
- 出处核对没有通过

整个请求最多两波。各路错开 400 毫秒启动，同时最多 5 路。每一路限时 180 秒，单次模型请求限时 90 秒。整次请求的思考步数名额是 5 乘以每路轮次，默认 5×8。

## 5. 一路里面怎么循环

每一路自己的图有三个节点。

**思考。** 把完整原题和最近 6 条观察交给模型。模型这一步只返回一个 JSON：要么调用一个工具，要么给出最终方案。一次回复里如果挤了多段工具 JSON，只解析并执行第一段，不会把后面的原文当成方案。看起来是工具调用但解析失败时，这一步记为无效，回到思考，不进入评分。

**执行工具。** 调用登记过的工具，把观察写回这一路。别的路看不到这些观察。

**收束。** 写成方案之后，独立监督者再看一遍。监督者最多做两次只读检索，不能把新资料写回这一路的证据。程序算出的出处和缺项优先于模型的判断。方案里「最安全」「最优」「建议采用本方案」只从送给监督者的副本里删掉。隔离、断电、砂轮防护只作记录，不会因此淘汰方案。监督者发现仍缺必填项时，这一路改成需要补充。

这一路会在下面的情况停下来。

| 条件 | 结果 |
| --- | --- |
| 同一个工具、同一组参数再查一次 | 按已有观察写方案 |
| 新观察和上一条的前 200 个字相同 | 停止再查 |
| 已经执行 4 次工具 | 下一步必须写方案 |
| 到达每路轮次上限，默认 8，硬顶 50 | 不再调用工具，整理方案 |
| 整次请求的步数名额用完 | 不再开始新的一步 |
| 剩余时间不足 8 秒 | 整理已有观察 |
| 单次工具超过 5 秒 | 记为工具超时，再整理方案 |
| `ask_user` 参数合格 | 这一路结束，不写方案 |

`ask_user` 参数不合格时，记一条观察，继续思考。

## 6. 工具

五路看到的工具表相同。

| 工具 | 作用 | 程序约束 |
| --- | --- | --- |
| `search_knowledge` | 检索本地笔记 | 领域留空当作机械。不是机械时直接说明没有该领域。命中带 `knowledge/文件#起-止` |
| `lookup_baseline` | 读取测点模板 | 对不上子系统时不默认主轴。发热、温升仍映射到主轴 |
| `lookup_grind_dialect` | 识别磨床家族 | 只识别家族，不给扭矩和间隙 |
| `ask_user` | 向用户提分叉 | 一路最多两个问题。编号只能是小写字母、数字和下划线。问句不超过 80 字 |
| `record_measurement` | 记下原文里的读数 | 只接受扭矩、间隙、压力，而且必须出现在用户原文里。拒绝时不回显这个数 |
| `search_mtkb` | 查本机案例库 | 品牌、型号、领域由程序填写。连不上写「MTKB 未连接」，超时写「MTKB 超时」 |

能识别的家族包括 STUDER、高桥、MIKROSA、鹰贝，以及外圆、内圆、无心、平面、万能、数控磨床。

`web_search` 默认没有。页面勾选或设置 `SAMA2_ALLOW_WEB=1` 才加入工具表。它走 DuckDuckGo，没有网址的条目会被丢掉。案例库地址默认是 `http://127.0.0.1:8765`，可用 `SAMA2_MTKB_URL` 改。

## 7. 什么方案可以交付

写完的方案先过出处。方案里的扭矩、间隙、压力必须和这一路工具观察里的写法一致。核对前会先统一写法：`N.m` 和 `Nm` 看成 `N·m`，`um` 看成 `μm`，数字和单位之间的空格去掉。`0.02` 不等于 `0.020`，也不等于 `0.2`。

笔记编号、案例编号、方案里写出的网址，都必须是这一路观察中的一段原文。用户随口写的数，没有经过 `record_measurement` 或补充观察，不算证据。

没通过的方案离开候选。五路都不通过时，页面只说明这次没有可交付方案，并列出没有出处的数值，不展示那些方案正文。

只要有一路向用户提问，这一轮就不评分、不交付维修步骤，正文只有汇总后的问题。各路已经写下的内容留在作者视图里，不作为第二套步骤。

## 8. 怎么选出一份

评判温度 0.1。模型给出五项分数和缺陷说明，程序计算加权分。每一项先夹到 0 到 10，总分保留两位小数。

**S = 0.30×准确性 + 0.25×安全性 + 0.20×可行性 + 0.15×完整性 + 0.10×简洁性**

| 代号 | 维度 | 权重 |
| --- | --- | --- |
| A | 故障定位准确性 | 0.30 |
| B | 操作安全性 | 0.25 |
| C | 现场可行性 | 0.20 |
| D | 方案完整性 | 0.15 |
| E | 简洁性 | 0.10 |

生成失败的方案不参加。分数相同时先比安全性，再比准确性，再比路号，所以不会有两份并列中选。

准确性审计只看第一名，给出准确性和可信度。它不另选冠军，也不改名次。页面把第一名、第二名和分项评分一起交给用户，由用户选择。

## 9. 页面上两层

作者开关关掉时，显示综合分第一名和第二名及评分。打开后能看到复杂度、提取出的事实、流程、每一路的思考和停因，以及第一名的审计。

需要补充时，输入框改成「补充回答」。原题留在会话里，下一次提交会接回去。网页搜索是单独的勾选，默认关闭。

## 10. 默认参数

| 参数 | 默认 |
| --- | --- |
| 提议温度 | 0.7 |
| 成稿温度 | 0.2 |
| 评判与监督温度 | 0.1 |
| 种子起点 | 1000，可用 `SAMA2_SEED_BASE` 改 |
| 每路轮次 | 8，硬顶 50，可用 `SAMA2_MAX_STEP` 改 |
| 每路时限 | 180 秒 |
| 单次模型时限 | 90 秒 |
| 真实工具次数 | 4 |
| 工具超时 | 5 秒 |
| 采样波次 | 最多 2 |
| 安全抽查阈值 | 低于 6 分则补满五路 |
| 模型接口 | `https://api.deepseek.com`，模型 `deepseek-chat` |

API Key 来自页面本次请求、环境变量 `SAMA2_API_KEY`，或本目录的 `settings.json`。`settings.json` 不进入版本库。
